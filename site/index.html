Glossary

Layers

Every text file is scanned by two independent extraction layers, run in parallel:

Layer 1 — Regex
Fast plain-text scan: URLs with a scheme (http, https, ftp, ws, wss), IPv4 addresses appearing in networking calls (connect, urlopen, requests…), and full/compressed IPv6. Private and loopback IPs are filtered out automatically.
Layer 2 — AST
Static resolution of obfuscated URLs by walking the Python syntax tree: constant folding of string literals, binary-operator concatenation ("http://" + "evil.com"), base64.b64decode(...) calls, f-strings with resolvable parts, and scope tracking of variables assigned earlier in the same function.

Results

What each column and badge in the table means:

Layer
Which layer produced the finding — regex or ast.
Method
How the URL was written in source: via_base64, via_concat, via_fstring, via_scope, raw_ip, or blank for a plain literal string.
Verdict badge
A package is flagged suspicious once any finding's Threat column is set (shortener, tunneling, exfiltration, ip_recon, malware_hosting, suspicious_tld, or punycode); otherwise it's clean. A bare IP address alone (raw_ip, shown under Method) doesn't count toward this verdict.
HTTP status badge
From --check-http: the final status code after following redirects — green for 2xx, amber for 3xx, red for 4xx/5xx.
Page title
The page's <title>, shown in italics, captured by --check-http when the request got a response.
Certificate badge
From --check-ssl: LE flags a Let's Encrypt-issued certificate (free, instant issuance makes it a common choice for throwaway malicious infrastructure); any other issuer is shown as plain text.
